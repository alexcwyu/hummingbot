Design decisions

Decision Rationale Tradeoff Evidence
Separate controllers from lifecycle-owning executors. Controller actions reuse modular execution, accounting and shutdown behavior. Mapping/configuration must match supported executor type; not all controllers/executors share simulation semantics. StrategyV2Base.on_tick (L312) / ExecutorOrchestrator.create_executor (L543) / BacktestingEngineBase.simulate_execution (L269)
Track orders before network submission. Failure/status reconciliation can identify client-owned in-flight orders consistently. Asynchronous fills may arrive after completion status; tracker uses bounded waiting before warning/processing incomplete information. ExchangePyBase._create_order (L400) / ClientOrderTracker._process_order_update (L267)

Workflow

V2 controller-to-order execution

Clock uses inherited TimeIterator tick mechanism; venue network API and event arrival order are external. No live connector session was exercised.

Diagram source
flowchart TD
  W0["Advance registered strategy clock tick."]
  W1["Check connector readiness, update controller state and determine actions."]
  W0 --> W1
  W2["Dispatch action, construct/start mapped executor."]
  W1 --> W2
  W3["Place remaining amount as order or Gateway swap."]
  W2 --> W3
  W4["Track/quantize/validate order then place through venue API."]
  W3 --> W4
  W5["Reconcile asynchronous fill/status events and trigger callbacks."]
  W4 --> W5
  W6["Record fill and market state."]
  W5 --> W6

  3. Dispatch action, construct/start mapped executor.. ExecutorOrchestrator.execute_action (L515) / ExecutorOrchestrator.create_executor (L543)
  4. Place remaining amount as order or Gateway swap.. OrderExecutor.place_open_order (L232)

Strengths and limits

Strengths

  • Order executor retries/renewals compute remaining amount, while tracker distinguishes creation/fill/completion events. OrderExecutor.place_open_order (L232) / ClientOrderTracker._process_order_update (L267)

Limitations

  • Backtest simulation is controller/executor-specific and follows historical feature rows; it does not establish identical venue orderbook/network behavior. BacktestingEngineBase.simulate_execution (L269) / ExchangePyBase._create_order (L400)
